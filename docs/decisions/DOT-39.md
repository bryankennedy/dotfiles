### DOT-39 — Hex comes from Anomaly's tap; the old data stays, and F17 stays the trigger

**Decision.** `nix-darwin/flake.nix` declares the tap `anomalyco/tap` and the cask `anomalyco/tap/hex` in place of `kitlangton-hex`. `scripts/hex.sh` sets the dictation hotkey to F17 through Hex's own CLI, with Hex running or stopped. The three Karabiner rules are unchanged: the middle mouse button, the fn key, and the Varmilo Pause key (and F15) each send F17. The old Hex data folder is left in place, and a dated copy of it sits outside the repo.

**What prompted it.** Hex moved from `kitlangton/Hex` to `anomalyco/hex`. The old repository's README says the Swift app is no longer maintained, and Hex 2.3.1 does not update itself to Hex 3. The install command is now `brew install --cask anomalyco/tap/hex`. The owner asked for the upgrade with a backup of the old data and the same trigger keys. DOT-25 had also noted that `scripts/hex.sh` still wrote F15 for the Hex 1 plist, which contradicted the Karabiner rules.

**What changes in Hex 3.** The bundle ID is `anomaly.hex`, signed by Anomaly, in place of `com.kitlangton.hex2`. macOS treats it as a new app, so Microphone and Accessibility are granted again, and the old Hex entries in Privacy & Security are removed by hand. The data folder is `~/Library/Application Support/hex` in place of `~/Library/Application Support/voice-control`. The release notes for 3.0.0 say Hex 3 imports nothing from the old folder and leaves it alone. Transformations live in `~/.config/hex/hex.config.ts`; the Mac had none.

**How the data was kept.** The settings file, the history file, the `onboarding-complete` marker, and the Parakeet model with its verification receipt were copied from `voice-control` to `hex` before the first launch. Hex 3 is the same Rust code base continued, so it read the old settings as its legacy shape and wrote them back in the new one. The model matched the catalog's digest and was accepted without a download. The receipt check compares the file's modification time to the nanosecond, so the copy used `cp -p -c`, which keeps it. The hotkey came over as F17. History came over whole. Before any of this, every old folder (`voice-control`, the Hex 1 container, the preferences file, the caches) and the old app bundle were copied to a dated folder under `~/Backups/hex/`, with a README that says how to roll back. The old `voice-control` folder is still in place as well.

**Why the swap was done by hand once.** Both casks install `/Applications/Hex.app`. `brew bundle` installs before it cleans up, so a switch with the new cask declared and the old one still installed would refuse to install over the existing app. The order was: quit Hex, `brew uninstall --cask kitlangton-hex` (which removes the app and not the data), then `brew install --cask anomalyco/tap/hex`. The flake's comment records this. The next `darwin-rebuild switch` finds the old cask gone and the new one present, so it changes nothing.

**Why F17, and why the script changed shape.** macOS binds F15 to brightness up and consumes it before Hex's event tap sees it, so every trigger sends F17 (commit `8059320`). Hex 3 rejects `fn` combined with a key, and accepts a function key alone, so the script sets `f17`, not `fn+f17`. Hex 1 kept its hotkey in a plist and the old script wrote it with PlistBuddy. Hex 3 has a `hex settings` command inside the app bundle: `settings set` changes the setting in the running app, and `settings apply` writes `settings.json` directly when Hex is stopped. The script uses one or the other, so it needs no knowledge of the settings file's shape. Both paths were run on 2026-11-04. Closes DOT-25.

**Not done here.** Hex 3 can use a mouse button as the shortcut on its own. The Karabiner rules stay, because they also serve the fn key and the Pause key, and one trigger for all three devices is simpler to reason about. The old `voice-control` folder is not deleted; the owner can delete it, and the backup, once Hex 3 has run for a while.
